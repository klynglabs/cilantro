## Findings considered and rejected

- **`bun audit` advisories** (protobufjs, adm-zip): transitive through
  `steam-user`; no direct fix available in this repo. Revisit when steam-user updates.
- **`as Steam.LogOnDetailsRefresh` / `as Steam.LogOnDetailsNamePass` casts**
  (`src/bot.ts`, `getCredentials`): needed because `@types/steam-user` lacks
  `renewRefreshTokens`.
- **`any[]` cast in `SteamEvents.bind`**: the standard way to iterate a mapped
  handler type; a typed alternative adds complexity for no safety gain.
- **Plaintext token storage, `convertRelativePath` wrapper, public readonly
  `Bot` fields**: rejected in the previous run for the same reasons; unchanged.
- **Redundant `if (!configFile.accounts)` guard** (previous run): superseded —
  plan 007 replaces the whole file and moves the check into the schema, where it
  also catches an empty list.
- **zod 4 migration**: no functional gain for this schema.
- **`stop()` hanging**: not real; `logOff()` always emits `disconnected`.
- **Login timeout**: steam-user retries connections internally, and a timeout
  would break the Steam Guard prompt, which can legitimately take minutes.
- **Performance**: a handful of long-lived connections; nothing to optimize.
- **Empty Steam Guard input exits the process** (`onSteamGuard`): deliberate
  "abort" behavior; out of scope.

## Direction (not planned; options for the maintainer)

- **Unattended Steam Guard**: accept an optional `sharedSecret` per account and
  generate codes with `steam-totp`. Removes the only interactive step, but
  requires users to extract their shared secret (Steam Desktop Authenticator
  or similar), which is a real security trade-off.
- **Literal or env-var config values**: allow `"password": "hunter2"` as well
  as env-var names. Friendlier setup, but ambiguous without a marker (e.g. a
  `$` prefix) and changes the documented config format.
- **CI workflow**: run `format:check`, `typecheck` and `test` on every push once
  plan 005 lands. Small and cheap; not requested this run.
