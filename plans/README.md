## Findings considered and rejected

- **Plaintext token storage** (`src/services/token.service.ts`): intentional
  design for a personal-use tool; encryption would add complexity with minimal
  real-world benefit in this threat model.
- **`convertRelativePath` trivial wrapper** (`src/utils/path.ts`): harmless
  indirection, not worth a plan.
- **`public readonly` on `Bot.logger`/`Bot.steam`**: minor encapsulation issue,
  no behavior impact, not worth a plan.
- **Redundant `if (!configFile.accounts)` guard** (`src/config.ts:6-8`): provides
  a clearer error message than a raw ZodError; intentional, not worth removing.
- **Per-account fault isolation** (direction finding): `process.exit(1)` on one
  account's `InvalidPassword` kills all bots — a real limitation, but addressing
  it requires a larger architectural change (per-bot error boundaries, lifecycle
  management). Deferred as a direction item, not planned here.
- **Literal-vs-env-var config UX** (direction finding): supporting both
  `"password": "literal"` and `"password": "$ENV_VAR"` in config.json would
  improve UX but requires changing `resolve-env.ts` and the schema. Noted in
  plan 003's maintenance section; not planned as a standalone plan.
